## 二、召回层深度问题

### 2. 协同过滤算法
**Q: ItemCF和UserCF有什么区别？各自适用什么场景？**

A: 
**ItemCF (物品协同过滤):**
- 基于物品相似度: 喜欢物品A的用户也喜欢物品B
- 优点: 结果可解释性强、更新频率低、适合物品更新慢的场景
- 缺点: 容易推荐热门物品、新物品冷启动困难
- 适用: 电商、新闻等物品相对稳定的场景

**UserCF (用户协同过滤):**
- 基于用户相似度: 相似用户有相似偏好
- 优点: 能发现小众兴趣、适合社交推荐
- 缺点: 用户矩阵更大、计算复杂度高、更新频繁
- 适用: 社交网络、兴趣社区

**我的项目中:**
- ItemCF占召回权重15%，用于捕捉短期兴趣
- UserCF占10%，用于发现长尾内容
- 两者互补，提升推荐覆盖度

**Q: 如何解决协同过滤的数据稀疏问题？**

A: 我采用了多种策略:
1. **矩阵分解**: 将稀疏的user-item矩阵分解为低维稠密矩阵
2. **引入side information**: 结合用户画像、物品属性等额外信息
3. **混合推荐**: 协同过滤 + 内容推荐 + 深度学习召回
4. **负采样优化**: 使用popularity-based采样，而不是随机采样
5. **正则化**: 防止过拟合，提升泛化能力

### 3. 双塔模型
**Q: 双塔模型的训练策略是什么？为什么这样设计？**

A: 
**训练策略: 对比学习 (Contrastive Learning)**

核心思想:
- 正样本: 用户实际交互的物品 (user-item pair)
- 负样本: batch内其他物品 (in-batch negatives)
- 损失函数: InfoNCE Loss

```python
# 相似度矩阵: (batch_size, batch_size)
similarity_matrix = user_vectors @ item_vectors.T / temperature

# 对角线是正样本，其他是负样本
loss = CrossEntropy(similarity_matrix, labels=diagonal_indices)
```

**为什么这样设计:**
1. **效率**: batch内负采样，无需额外采样
2. **难负样本**: batch内的物品都是高质量的，作为负样本更有挑战性
3. **可扩展**: 向量化计算，GPU加速

**在线服务:**
- 离线生成所有物品向量，存入Faiss索引
- 用户请求时，计算用户向量
- ANN检索，Top-K召回
- 响应时间 < 10ms

**Q: 双塔模型的向量如何更新？增量更新还是全量？**

A: 采用**增量更新 + 定期全量**的策略:

**增量更新 (每小时):**
- 只更新新增物品的向量
- 使用固定的Item Tower参数
- 快速上线新内容

**全量更新 (每天):**
- 重新训练整个模型
- 使用最近7天的行为数据
- 捕捉趋势变化

**用户向量:**
- 实时计算 (推理时间<5ms)
- 或缓存热门用户向量 (Redis, TTL=1小时)

### 4. 图召回 (DeepWalk)
**Q: DeepWalk在推荐系统中如何应用？**

A:
**基本思路:**
1. 构建用户-物品交互图
2. 随机游走生成序列 (类似自然语言的句子)
3. 使用Word2Vec学习节点embedding
4. 相似节点在向量空间中距离近

**在我的项目中:**
- 构建二部图: User ↔ Item
- 游走长度: 80步
- 游走次数: 每个节点10次
- Embedding维度: 128

**优势:**
- 捕捉高阶关系 (不只是直接交互)
- 发现潜在的兴趣链路
- 适合冷启动 (新用户可以通过少量行为游走到相关物品)

**挑战与优化:**
- 图更新频率: 每天增量更新
- 大图存储: 使用图数据库 (Neo4j) 或分布式图计算 (GraphX)
- 游走优化: 采用有偏游走 (node2vec) 平衡BFS和DFS

## 三、排序层深度问题

### 5. DIN模型详解
**Q: DIN的注意力机制为什么比传统方法好？**

A:
**传统方法的问题:**
- 将用户历史行为pooling成一个固定向量 (sum/average)
- 所有候选物品用同一个用户表示
- 忽略了用户兴趣的多样性

**DIN的改进:**
```
传统: User Embedding = Average(历史行为)
DIN:   User Interest = Attention(候选物品, 历史行为)
```

**注意力机制:**
1. Query: 候选物品embedding
2. Keys: 用户历史行为序列
3. 计算每个历史行为与候选物品的相关性
4. 加权求和 → 动态用户兴趣表示

**效果:**
- 不同候选物品激活不同的历史兴趣
- 局部激活原理 (Local Activation)
- CTR提升12% (在我的项目中)

**Q: DIN有哪些改进版本？各自特点是什么？**

A:
**DIEN (Deep Interest Evolution Network):**
- 增加兴趣演化层 (GRU)
- 建模兴趣随时间的变化
- 适合长序列场景

**DSIN (Deep Session Interest Network):**
- 引入session概念
- 分会话建模兴趣
- 适合多session场景 (如购物网站)

**MIMN (Multi-channel user Interest Memory Network):**
- 使用记忆网络存储长期兴趣
- 支持超长序列 (1000+)
- UIC (User Interest Center) 架构

**在项目中的选择:**
- 初期: DIN (简单高效)
- 优化方向: DIEN (建模兴趣演化)
- 长期规划: MIMN (支持更长历史)

### 6. 特征工程
**Q: 你们的特征系统是如何设计的？如何保证低延迟？**

A:
**特征分层架构:**

```
离线特征 (T+1更新)
├── 用户画像: 年龄、性别、城市、注册天数
├── 统计特征: 7日点击数、播放时长、偏好类目
└── 交叉特征: user×category历史交互

实时特征 (<100ms)
├── 实时CTR: 物品近1小时点击率
├── 用户状态: 当前session行为
└── 上下文: 时间、位置、网络
```

**低延迟保证:**
1. **Redis缓存**
   - 热点特征预加载
   - 多级缓存: 本地缓存 + Redis
   - 命中率 > 85%

2. **特征预计算**
   - 离线特征定期batch更新
   - 实时特征增量更新 (Flink)
   - 避免在线复杂计算

3. **特征精简**
   - 特征重要性分析 (SHAP)
   - 移除低价值特征
   - 从500+维 → 200维

4. **并行获取**
   - 异步IO
   - 用户特征和物品特征并行获取
   - 超时降级策略

**Q: 如何处理特征延迟问题？**

A:
**实时特征 vs 离线特征的Trade-off:**

| 特征类型 | 更新频率 | 延迟 | 实现 |
|---------|---------|------|------|
| 实时特征 | 秒级 | <100ms | Redis + Flink |
| 准实时特征 | 分钟级 | <5min | Flink滑动窗口 |
| 离线特征 | T+1 | 1天 | Spark批处理 |

**处理策略:**
1. **特征分级**: 重要特征实时化，次要特征T+1
2. **渐进式更新**: 新特征先T+1，稳定后实时化
3. **特征回填**: 离线特征缺失时用历史均值填充
4. **Delayed Feedback处理**: 建模label延迟（如次日留存）

## 四、重排与业务优化

### 7. 多样性优化
**Q: 如何在保证相关性的同时提升多样性？**

A:
**多样性的重要性:**
- 避免推荐结果同质化
- 提升用户探索性
- 长期用户价值

**我的实现方案:**

**1. MMR算法 (Maximal Marginal Relevance)**
```
MMR = arg max [λ × Relevance - (1-λ) × Similarity]

λ=0.5 时平衡相关性和多样性
```

**2. 多维度多样性:**
- 类目多样性: 不同内容类别
- 作者多样性: 避免单一作者霸屏
- 时间多样性: 新老内容混合
- 风格多样性: 基于内容embedding的距离

**3. 业务规则:**
- 同一作者连续不超过2个
- 同一类目不超过3个
- 每5个插入1个新内容

**效果:**
- 类目多样性提升18%
- 用户session时长提升10%
- 跳出率下降5%

**Q: 多样性和准确性如何平衡？**

A:
**动态调整策略:**
1. **用户分层**
   - 新用户: λ=0.3 (更多探索)
   - 活跃用户: λ=0.5 (平衡)
   - 深度用户: λ=0.7 (精准推荐)

2. **场景化调整**
   - 首页推荐: 多样性优先
   - 相关推荐: 相关性优先
   - 发现页: 纯多样性

3. **A/B测试优化**
   - 实验不同λ值
   - 监控CTR、时长、留存等多指标
   - 找到最优平衡点

### 8. 冷启动问题
**Q: 如何解决用户和物品的冷启动问题？**

A:
**物品冷启动 (新视频如何获得曝光):**

1. **内容画像匹配**
   - 提取新视频的标签、类目、作者
   - 匹配到相似物品的用户群
   - 基于内容的召回

2. **探索流量分配**
   - 新内容自动获得基础流量 (如1000次曝光)
   - Thompson Sampling: 平衡探索与利用
   - 根据早期表现决定后续流量

3. **冷启动加权**
   - 发布24小时内的内容加权1.2倍
   - 在重排层提升位置
   - 避免新内容被淹没

4. **迁移学习**
   - 利用相似内容的特征
   - Warm-up: 用相似物品的embedding初始化

**用户冷启动 (新用户如何推荐):**

1. **引导式推荐**
   - 新用户注册时选择兴趣标签
   - 根据标签推荐初始内容

2. **人口统计学推荐**
   - 基于年龄、性别、地域
   - 推荐该群体的热门内容

3. **快速建模**
   - 用户有3-5次行为后立即建模
   - 使用轻量级模型快速响应

4. **跨域迁移**
   - 利用同公司其他产品的数据
   - 联邦学习: 保护隐私的迁移

### 10. AB测试
**Q: 如何进行推荐系统的AB测试？如何评估效果？**

A:
**实验设计:**

1. **分流策略**
   - 基于用户ID哈希分桶
   - 保证同一用户始终在同一组
   - 流量比例: 对照组50% vs 实验组50%

2. **核心指标**
   - 北极星指标: 人均观看时长
   - 过程指标: CTR, 完播率, 互动率
   - 反向指标: 跳出率, 负反馈率
   - 多样性指标: 类目分布熵

3. **统计检验**
   - 卡方检验 (CTR等比例指标)
   - t检验 (时长等连续指标)
   - p-value < 0.05 才上线
   - 最小样本量: 每组10000+用户

4. **实验周期**
   - 新模型: 至少7天
   - 小优化: 3-5天
   - 覆盖工作日和周末

**实际案例:**
```
实验: DIN vs DeepFM
对照组 (DeepFM): CTR=12.5%, 时长=45min
实验组 (DIN):    CTR=14.2%, 时长=55min
提升:            +13.6%,     +22.2%
p-value:         <0.001
结论: DIN效果显著，全量上线
```

### 12. 数据偏差
**Q: 推荐系统中有哪些偏差？如何解决？**

A:
**主要偏差:**

1. **位置偏差 (Position Bias)**
   - 问题: 靠前的位置点击率更高
   - 解决: 
     - Position Embedding
     - IPS (Inverse Propensity Score)加权
     - 在loss中除以位置权重

2. **曝光偏差 (Selection Bias)**
   - 问题: 只能观察到推荐过的物品
   - 解决:
     - 探索策略: ε-greedy
     - 随机曝光: 10%流量随机推荐
     - Causal Inference方法

3. **流行度偏差 (Popularity Bias)**
   - 问题: 热门物品曝光更多，形成马太效应
   - 解决:
     - 负采样时降低热门物品权重
     - 长尾物品加权
     - Debias模型

**因果推断方法:**
- IPS: $\hat{R} = \frac{y}{p(x)}$
- DR: Doubly Robust = IPS + Imputation
- 提升模型泛化性

## 面试技巧

### 回答套路
1. **背景 (Background)**: 为什么要做这个
2. **方案 (Approach)**: 怎么做的
3. **结果 (Result)**: 效果如何
4. **反思 (Reflection)**: 还可以怎么改进

### 注意事项
- 避免过于绝对的表述
- 承认局限性，展示思考深度
- 准备至少3个可以深入的技术点
- 对待优化方向要有具体想法，不能只说"可以用XX"

### 常见陷阱
- ❌ "这个模型很简单，就是..."
- ✅ "考虑到工程效率，我们选择了..."
- ❌ "我没遇到过这个问题"
- ✅ "虽然我没直接处理过，但我的思路是..."
